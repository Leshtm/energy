# energy — сборки оверлея «Энергия» для магнитолы Voyah

Здесь лежат **только собранные APK**. Исходного кода в этом репозитории нет
и не будет: исходники в приватном репозитории, а сюда попадают готовые
сборки, которыми обновляется приложение на магнитоле.

## Что внутри

| где | что это |
|---|---|
| `builds/energy-<сборка>.apk` | собранный и подписанный APK |
| `builds/version-<сборка>.json` | описание сборки: номер, смысловая версия, ссылка на ассет релиза, SHA-256 |
| Releases | готовые релизы: APK и `version.json`, который читает приложение |

## Как ставится обновление

Приложение по кнопке «Проверить обновление» спрашивает адрес, зашитый в
`Main.UPDATE_URL`, читает оттуда `version.json` и, если `versionCode` в
ответе больше установленного, скачивает APK и открывает штатный установщик.
Подтверждение установки даёт человек — одним тапом на «Энергия» ничего не
ставится.

Постоянный адрес ответа:

```
https://github.com/Leshtm/energy/releases/latest/download/version.json
```

Сборки подписаны одним ключом, поэтому обновление встаёт только поверх
такой же сборки: Android не примет файл с чужой подписью.

## Как публикуется новая сборка

1. APK кладётся в `builds/` под именем `energy-<сборка>.apk`, рядом —
   `version-<сборка>.json` с номером, смысловой версией, ссылкой на ассет
   релиза и SHA-256 файла.
2. Запускается воркфлоу «Публикация сборки в релиз» (Actions → Run
   workflow) с номером сборки.
3. Воркфлоу сверяет SHA-256 APK с заявленным, сверяет ссылку в
   `version.json` с тем, что сам выкладывает, и создаёт или обновляет
   релиз `v<сборка>` с двумя ассетами: APK и `version.json`.

Внешнего хостинга в этой схеме нет: всё нужное лежит в этом же репозитории.
